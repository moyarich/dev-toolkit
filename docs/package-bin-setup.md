# Package setup with CLI binaries

Use this pattern for packages in `dev-toolkit` that expose one or more command-line binaries.

This follows the same conventions used by packages such as `packages/vs-code-ext-tools`.

## Folder tree

```text
packages/
└── my-package/
    ├── package.json
    ├── tsconfig.json
    ├── vite.config.ts
    ├── README.md
    ├── CHANGELOG.md
    ├── src/
    │   ├── cli/
    │   │   ├── command-a.ts
    │   │   └── command-b.ts
    │   └── ...
    ├── tests/
    │   ├── command-a-cli.test.ts
    │   └── command-b-cli.test.ts
    └── bin/
        ├── command-a.mjs
        └── command-b.mjs
```

The `bin/` directory is generated by the build. Do not treat generated files there as the source of truth.

## package.json

A typical package looks like:

```json
{
  "name": "@moyarich/my-package",
  "version": "0.1.0",
  "description": "Reusable development tooling.",
  "type": "module",
  "bin": {
    "command-a": "./bin/command-a.mjs",
    "command-b": "./bin/command-b.mjs"
  },
  "files": [
    "bin",
    "src",
    "README.md",
    "CHANGELOG.md"
  ],
  "engines": {
    "node": ">=24"
  },
  "scripts": {
    "build": "vite build --config vite.config.ts",
    "test": "vitest run",
    "typecheck": "tsc -p tsconfig.json"
  },
  "repository": {
    "type": "git",
    "url": "git+https://github.com/moyarich/dev-toolkit.git",
    "directory": "packages/my-package"
  },
  "publishConfig": {
    "registry": "https://npm.pkg.github.com",
    "access": "public"
  },
  "devDependencies": {
    "@moyarich/vite-plugin-package-bin": "0.1.0"
  },
  "license": "MIT"
}
```

### Important fields

- `name`: use the `@moyarich/` scope and match the package folder conceptually.
- `type: "module"`: packages use ESM.
- `bin`: maps CLI command names to generated files under `bin/`.
- `files`: controls what is included when the package is published.
- `engines.node`: keep this aligned with the repository-supported Node version.
- `repository.directory`: points consumers back to the package inside the monorepo.
- `publishConfig`: configures GitHub Packages when the package is published there.

## CLI source

Put CLI entry points under:

```text
src/cli/
```

Example:

```ts
#!/usr/bin/env node

import { Command } from "commander";

const program = new Command();

program
  .name("command-a")
  .description("Example CLI command")
  .option("--dry-run", "Preview without making changes")
  .action((options) => {
    if (options.dryRun) {
      console.log("Dry run");
      return;
    }

    console.log("Run");
  });

program.parse();
```

The TypeScript source is the source of truth. The corresponding `bin/*.mjs` file is produced during the Vite build.

## Vite configuration

Use `@moyarich/vite-plugin-package-bin` to discover and build CLI entry points:

```ts
import { defineConfig } from "vite";
import { packageBinBuild } from "@moyarich/vite-plugin-package-bin";

export default defineConfig({
  plugins: [
    packageBinBuild({
      entries: {
        pattern: "src/cli/**/*.ts",
      },
      emptyOutDir: true,
    }),
  ],
});
```

If the CLI imports dependencies that should remain external at runtime, specify them:

```ts
export default defineConfig({
  plugins: [
    packageBinBuild({
      entries: {
        pattern: "src/cli/**/*.ts",
      },
      emptyOutDir: true,
      external: [/^@inquirer\//, "chalk", "commander"],
    }),
  ],
});
```

The plugin turns files such as:

```text
src/cli/command-a.ts
src/cli/command-b.ts
```

into:

```text
bin/command-a.mjs
bin/command-b.mjs
```

## TypeScript configuration

Use the package-level TypeScript configuration:

```json
{
  "compilerOptions": {
    "target": "ES2024",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "types": ["node"],
    "skipLibCheck": true
  },
  "include": [
    "src/**/*.ts",
    "vite.config.ts"
  ]
}
```

If the package contains other TypeScript sources such as migration scripts, include them explicitly:

```json
{
  "include": [
    "src/**/*.ts",
    "scripts/**/*.ts",
    "vite.config.ts"
  ]
}
```

## Tests

Keep package tests under:

```text
tests/
```

Prefer separate tests for reusable logic and CLI behavior.

Example:

```text
tests/
├── command-a.test.ts
└── command-a-cli.test.ts
```

Run:

```bash
npm test --workspace @moyarich/my-package
```

For CLI tests, prefer invoking the same exported behavior used by the CLI rather than testing only generated `bin/` text.

## Build and verify

From the repository root:

```bash
npm run build --workspace @moyarich/my-package
npm run typecheck --workspace @moyarich/my-package
npm test --workspace @moyarich/my-package
```

After building, verify the generated binaries:

```bash
ls packages/my-package/bin
```

You can run one directly:

```bash
node packages/my-package/bin/command-a.mjs --help
```

## Adding a new binary

Add another TypeScript entry:

```text
src/cli/new-command.ts
```

Add its package mapping:

```json
{
  "bin": {
    "command-a": "./bin/command-a.mjs",
    "new-command": "./bin/new-command.mjs"
  }
}
```

Because the Vite entry pattern is `src/cli/**/*.ts`, the new source file is automatically included in the build.

## Publishing

Before publishing, run:

```bash
npm run build --workspace @moyarich/my-package
npm run typecheck --workspace @moyarich/my-package
npm test --workspace @moyarich/my-package
```

For GitHub Packages, package metadata should include:

```json
{
  "publishConfig": {
    "registry": "https://npm.pkg.github.com",
    "access": "public"
  }
}
```

Then use the repository's reusable package release/publish workflows instead of maintaining a separate publish implementation in each package.

## Checklist

- package lives directly under `packages/<hyphenated-name>/`
- scoped npm name uses `@moyarich/<hyphenated-name>`
- source CLI files live under `src/cli/`
- generated binaries live under `bin/`
- `package.json#bin` points only to generated `.mjs` files
- Vite uses `@moyarich/vite-plugin-package-bin`
- `tsconfig.json` uses NodeNext + strict + noEmit
- package defines `build`, `test`, and `typecheck`
- package metadata includes `repository.directory`
- publishable files are declared with `files`
- generated binaries are built before publish
- package tests run independently through npm workspaces


## Hello World package example

The following example creates a complete CLI package named `@moyarich/hello-world`.

### 1. Create the package folders

From the repository root:

```bash
mkdir -p packages/hello-world/src/cli
mkdir -p packages/hello-world/tests
```

The package will look like:

```text
packages/
└── hello-world/
    ├── package.json
    ├── tsconfig.json
    ├── vite.config.ts
    ├── README.md
    ├── src/
    │   ├── hello.ts
    │   └── cli/
    │       └── hello-world.ts
    ├── tests/
    │   └── hello.test.ts
    └── bin/
        └── hello-world.mjs
```

The `bin/hello-world.mjs` file does not need to be created manually. It is generated by the build.

### 2. Create package.json

Create `packages/hello-world/package.json`:

```json
{
  "name": "@moyarich/hello-world",
  "version": "0.1.0",
  "description": "Example dev-toolkit CLI package.",
  "type": "module",
  "bin": {
    "hello-world": "./bin/hello-world.mjs"
  },
  "files": [
    "bin",
    "src",
    "README.md"
  ],
  "engines": {
    "node": ">=24"
  },
  "scripts": {
    "build": "vite build --config vite.config.ts",
    "test": "vitest run",
    "typecheck": "tsc -p tsconfig.json"
  },
  "repository": {
    "type": "git",
    "url": "git+https://github.com/moyarich/dev-toolkit.git",
    "directory": "packages/hello-world"
  },
  "publishConfig": {
    "registry": "https://npm.pkg.github.com",
    "access": "public"
  },
  "devDependencies": {
    "@moyarich/vite-plugin-package-bin": "0.1.0"
  },
  "license": "MIT"
}
```

Because the repository root already declares `packages/*` as an npm workspace, no additional root workspace configuration is required.

### 3. Add reusable package logic

Create `packages/hello-world/src/hello.ts`:

```ts
/**
 * Build a greeting for a supplied name.
 */
export function hello(name = "World"): string {
  return `Hello, ${name}!`;
}
```

Keeping the reusable behavior outside the CLI makes it easy to test without spawning a process.

### 4. Add the CLI entry point

Create `packages/hello-world/src/cli/hello-world.ts`:

```ts
import { hello } from "../hello.js";

const name = process.argv[2] ?? "World";

console.log(hello(name));
```

The source filename determines the generated binary filename:

```text
src/cli/hello-world.ts
        ↓
bin/hello-world.mjs
```

and `package.json#bin` exposes that generated file as the `hello-world` command.

### 5. Configure Vite

Create `packages/hello-world/vite.config.ts`:

```ts
import { defineConfig } from "vite";
import { packageBinBuild } from "@moyarich/vite-plugin-package-bin";

export default defineConfig({
  plugins: [
    packageBinBuild({
      entries: {
        pattern: "src/cli/**/*.ts",
      },
      emptyOutDir: true,
    }),
  ],
});
```

This discovers all TypeScript files under `src/cli/` and builds each one into `bin/*.mjs`.

### 6. Configure TypeScript

Create `packages/hello-world/tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2024",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "types": ["node"],
    "skipLibCheck": true
  },
  "include": [
    "src/**/*.ts",
    "tests/**/*.ts",
    "vite.config.ts"
  ]
}
```

### 7. Add a test

Create `packages/hello-world/tests/hello.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import { hello } from "../src/hello.js";

describe("hello", () => {
  it("greets World by default", () => {
    expect(hello()).toBe("Hello, World!");
  });

  it("greets a supplied name", () => {
    expect(hello("Moya")).toBe("Hello, Moya!");
  });
});
```

### 8. Build the package

From the repository root:

```bash
npm install
npm run build --workspace @moyarich/hello-world
```

After the build:

```text
packages/hello-world/
└── bin/
    └── hello-world.mjs
```

### 9. Run the generated binary

Run it directly:

```bash
node packages/hello-world/bin/hello-world.mjs
```

Expected output:

```text
Hello, World!
```

Pass a name:

```bash
node packages/hello-world/bin/hello-world.mjs Moya
```

Expected output:

```text
Hello, Moya!
```

### 10. Run it through npm workspaces

You can execute the package binary through its workspace:

```bash
npm exec --workspace @moyarich/hello-world -- hello-world Moya
```

Expected output:

```text
Hello, Moya!
```

### 11. Verify the package

Run all package checks:

```bash
npm run build --workspace @moyarich/hello-world
npm run typecheck --workspace @moyarich/hello-world
npm test --workspace @moyarich/hello-world
```

You can also inspect what npm would publish:

```bash
npm pack --workspace @moyarich/hello-world --dry-run
```

The package archive should include the generated binary and the files declared in `package.json#files`.

### 12. Add another command

To add another CLI command, create another file:

```text
src/cli/goodbye.ts
```

and add it to `package.json#bin`:

```json
{
  "bin": {
    "hello-world": "./bin/hello-world.mjs",
    "goodbye": "./bin/goodbye.mjs"
  }
}
```

No Vite configuration change is required because `src/cli/**/*.ts` already discovers the new CLI entry point.

### End-to-end flow

```text
src/hello.ts
    │
    └── reusable application logic

src/cli/hello-world.ts
    │
    ▼
vite.config.ts
    │
    ▼
@moyarich/vite-plugin-package-bin
    │
    ▼
bin/hello-world.mjs
    │
    ▼
package.json#bin
    │
    ▼
hello-world
```

This keeps application logic testable, CLI source in TypeScript, and published binaries generated consistently across `dev-toolkit` packages.

# Publish a VS Code extension

`vs-code-publish` provides the package's reusable local extension publishing CLI.

Inspect the command directly after building the package:

```sh
node packages/vs-code-ext-tools/dist/bin/vs-code-publish.mjs --help
```

Or, when installed as a package:

```sh
vs-code-publish --help
```

The CLI uses Commander for command parsing and the package's reusable publishing implementation from `src/publish_ext.ts`.

## Reusable GitHub Actions workflow

`.github/workflows/reusable_vscode-extension-publish.yml` provides the CI/CD publishing path for extension repositories. It carries forward the release safeguards used by JotebookSync:

- dry-run is the default;
- real publishes pass through a protected `release` environment;
- the requested version must match `package.json`;
- the canonical `v<version>` tag is verified by default;
- the matching GitHub draft release is verified before publication;
- the workflow packages and retains the VSIX artifact;
- Marketplace publication happens before the GitHub draft is promoted;
- `already-published` mode can recover when the Marketplace version already exists;
- the workflow summary records the resolved version, tag, artifact, Marketplace state, and GitHub Release state.

A consuming repository can keep its repository-specific `workflow_dispatch` UI and delegate the implementation:

```yaml
jobs:
  publish:
    uses: moyarich/dev-toolkit/.github/workflows/reusable_vscode-extension-publish.yml@main
    with:
      target-branch: ${{ inputs.target-branch }}
      dry-run: ${{ inputs.dry-run }}
      version: ${{ inputs.version }}
      marketplace-mode: ${{ inputs.marketplace-mode }}
    secrets:
      vsce-pat: ${{ secrets.VSCE_PAT }}
```

For a monorepo extension, set `extension-directory`. Validation commands and additional `vsce package` arguments are inputs so callers can preserve extension-specific checks without copying the publishing workflow.

The caller should normally provide the manual trigger, concurrency policy, and any repository-specific display names. The reusable workflow owns the publish mechanics and safety checks.

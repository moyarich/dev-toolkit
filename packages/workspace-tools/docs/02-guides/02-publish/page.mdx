# Publishing packages

Validate without publishing:

```sh
workspace-publish css-expand-collapse --dry-run
```

A dry run reports Git-tag readiness without failing for a missing or mismatched release tag. The JSON result includes `verifyGitTag`, `gitTags`, `canPublish`, and the reason when publishing is blocked.

Publish to GitHub Packages:

```sh
workspace-publish css-expand-collapse --registry=github
```

Stage a release for npm:

```sh
workspace-publish css-expand-collapse --registry=npm
```

Before a real publish, Git tag verification is enabled by default. The matching `<selector>@<package.json.version>` tag must exist and point to `HEAD`. A missing tag or a tag on another commit fails the publish before package validation or registry mutation.

To intentionally bypass this condition:

```sh
workspace-publish css-expand-collapse --no-verify-git-tag
```

If the matching tag is valid but the package version already exists in the selected registry, that destination is skipped with reason `already-published`.

Use `--registry=both` for both destinations. `--tag=<tag>` controls the npm distribution tag and `--access=public|restricted` controls access.

Before publishing a missing registry version, the tool runs each package's `typecheck`, `test`, and `build` scripts when present, followed by `npm pack --dry-run`.
